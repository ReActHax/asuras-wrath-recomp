## 2. Building

From the *Developer Command Prompt for VS 2022* (Clang and CMake components):

```bat
package_release.bat
```

or manually:

```bat
cmake --preset win-amd64-release -DREXGLUE_USE_VULKAN=ON -DREXGLUE_USE_D3D12=ON -DREXGLUE_ENABLE_FIDELITYFX=ON
cmake --build out/build/win-amd64-release --parallel
copy /Y out\build\win-amd64-release\asura_wrath_recomp.exe out\dist\asura_wrath_recomp_windows_x86_64\
copy /Y tools\rexglue\out\win-amd64\*.dll out\dist\asura_wrath_recomp_windows_x86_64\
```

Pitfalls:
- Don't use `build.bat --package` (inherited from the original project): it
  deletes `out\dist`, including `extracted\` and the settings.
- The code generator needs `extracted\default.xex` **and** `default.xexp` at
  the repository root; it applies the title update patch itself. Without the
  `.xexp` it generates base-game code that doesn't match `includes\funcs.toml`.
- Force a regeneration by deleting `generated\default\codegen.build.stamp`.
- FidelityFX writes its DLLs to `bin\` at the root; the SDK copies them next to
  `rexruntime.dll` (otherwise `0xC0000135` at startup).
- `REXGLUE_WIN_DEBUG_SYMBOLS=ON` produces PDBs for the SDK modules (crash
  analysis with a minidump).
- PageHeap (heap corruption diagnosis) makes the game very slow: keep it off.

## 3. How the game patches work

The recompiled functions are weak symbols named `sub_XXXXXXXX` (guest address).
`REX_HOOK_RAW(sub_X)` replaces one and can call the original through
`__imp__sub_X`. Mid-function hooks are declared with `[[midasm_hook]]` in the
codegen TOML. Every address below is for **title update 1** (the base game
addresses differ, most by +0x10).

### `src/asura_patches.cpp`
- **60 FPS** (`asura_60fps`, F6): present interval 2 → 1 in `sub_8299A630`
  (device + 14000) and game speed scale through the constant used by
  `sub_824D71A8` (0x8207FB18). Found from boma's Xenia Canary patch.
- **Post-process toggle** (`asura_disable_postprocess`): `sub_827404C0` skipped
  for the callers with LR 0x8273F944 / 0x8273FAA0 / 0x8273FC0C / 0x82742208 /
  0x82742224.
- **Logo skip** (`asura_skip_logos`): the logo movies are redirected (file-open
  filter) to one-frame copies created in `BCGame\Movies\AsuraShortLogos`
  before the virtual file system is mounted. A Bink file is cut to one frame by
  setting frames = 1, largest frame = size of that frame, file size = end − 8.
  Hiding the files instead gives a black screen.
- Hotkeys: F6 (30/60 FPS), F8 (turbo).

### `src/asura_config_patch.cpp` — effect toggles
UE3 reads its settings from `CookedXbox360\Coalesced_<LANG>.bin`. Patched
copies are written to `CookedXbox360\AsuraPatched\` (with a `settings.txt`
fingerprint) and file opens are redirected to them. Coalesced format: big
endian integers, strings with a positive length = ANSI, negative = UTF-16LE.
The file size must not change (file table), so the size difference is
compensated in the `#TEXTUREGROUP_*` keys. `asura_fx_texture_detail` lowers
the texture groups' LOD bias (sharper textures, more memory).

### `src/asura_cheats.cpp` — F9 menu
ImGui dialog: trainer checkboxes, a list of user values (edit / freeze every
10 ms, saved to `asura_cheats.txt` as `type|address|value|name`) and a memory
search (32-bit int, float, 16-bit int, byte; equal / changed / unchanged /
increased / decreased; up to 10 million results). Guest memory is big endian;
the heaps are `0x40000000+` and the physical views `0xA/0xC/0xE0000000`.
Cheats are deliberately not cvars (not saved in the toml, off at each launch).
`IsAppOverlayOpen()` stops the pad from reaching the game while the menu has
the mouse.

### `src/asura_trainer.cpp`
Reproduces two cheats of the AxR / RETROBYTE / XYZEngine Aurora trainer:
- **God mode**: hook on `sub_8229CD10` (health write). Writes the maximum when
  the destination matches the player's health record (array size 1, max in
  {500, 1500, 5000}, signature words at dest−224 = 0x20702800 and
  dest−276 = 0x821A28F0).
- **Instant burst**: hook on `sub_8229E2A8` (float copy), when the target is
  1000.0 and r15 = 0x40515700.
- "Instant wrath" was dropped: the gauge drives scripted sequences, and the
  only reliable hook (FMin, 0x82253E68) affects the whole game.

### `includes/funcs.toml`
Function boundaries the analyzer misses, recomputed for title update 1 (most
+0x10; a few moved more: 0x82CB68D8, 0x823C3B58, 0x823A2940, 0x8239CFC0,
0x8236B938, 0x824C1338, 0x825F2E40, 0x829C4750, 0x829C4768; unchanged:
0x8224F150, 0x8225DB18, 0x822D8C78, 0x822D8798). Verified by comparing the
functions' code.

## 4. SDK changes (`tools/rexglue`)

- **Startup crash** (`0xC0000409`): `GetExecutablePath` used `_get_wpgmptr`,
  null without a `wmain` entry point → `GetModuleFileNameW`.
- **Heap corruption** (`0xC0000374`): `InputSystem::RefreshDevices` rebuilt
  the controller list from several threads → `std::recursive_mutex`. Found with
  PageHeap + minidump + PDB.
- **Input** (`src/input/sdl/sdl_input_driver.cpp`): press latch
  (`input_press_latch*`, a press between two reads is replayed) and turbo
  (`input_turbo*`, auto-repeat of held buttons).
- **DLC**: `ContentManager::InstallContentFromDirectory`, cvar
  `content_install_dir` (default `dlc`, relative to the user data folder);
  packages are installed after `PrepareModuleLaunch`.
- **File-open filter** (`rex/system/file_open_filter.h`, used in
  `NtCreateFile`): hide (empty string) or redirect guest file opens.
- **`ReXApp::IsAppOverlayOpen()`**.
- **FidelityFX DLL copy** next to `rexruntime`.
- **Texture replacement / dumping**: see
  [TEXTURE_MODDING.md](TEXTURE_MODDING.md#technical-details). Shared code in
  `src/graphics/pipeline/texture/replacement.{h,cpp}`; D3D12 swaps the
  resource (SRV descriptors keyed by replacement id, `TextureSRVKey` carries a
  resource generation so cached descriptor tables are refreshed); Vulkan swaps
  the image (views keyed by replacement id, readback through
  `CmdCopyImageToBufferEmplace`). The folder comes from
  `GraphicsSystem::InitializeShaderStorage` (parent of the cache folder).
  Lesson learned: hash the data as the GPU sees it — guest CPU memory can be
  stale when UE3 moves textures with the GPU.

## 5. Launcher (`tools/launcher/AsuraLauncher.cs`)

C# 5 / .NET Framework 4 WinForms, built by the `csc.exe` shipped with Windows
(no dependency). Contains:
- an XDVDFS reader (Xbox 360 disc image; game partition at 0, 0x2080000,
  0xFD90000 or 0x18300000; directory entries form a binary tree);
- an STFS reader (title update package: extracts `default.xexp`);
- MD5 checks: `default.xex` `6e1d309f85459b4e5b7200e12d1d9449`,
  `default.xexp` (TU1) `41a6522e92213cbe70410fcff8002b0c`;
- the settings editor (rewrites `key = value` lines in the toml, keeps the
  rest); interface language in `AsuraLauncher.ini`.

## 6. Decisions and findings

- `resolution_scale` > 1 is very expensive (EDRAM emulation at that scale,
  post-process passes): recommend 1× + FSR 1. `fsr2`/`fsr3` have no motion
  vectors here.
- Turbo only on B by default: the mashing QTEs seem to use B only, and Y keeps
  rapid fire. "Turbo only during QTEs" was dropped (QTE logic is in
  UnrealScript, expensive to detect).
- Ultrawide: judged too hard (fixed 720p, HUD, cutscenes).
- Vulkan: texture replacement works, but the renderer has many glitches in
  this game → D3D12 is the default.
- Languages: the game contains English, Japanese, German, French, Spanish and
  Italian text (`Coalesced_INT/JPN/DEU/FRA/ITA/ESN.bin`), English and Japanese
  voices.
- Never commit game files, title update, DLC or trainer files.
